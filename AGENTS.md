# Custom Developer Guidelines

- **Over-the-Air (OTA) vs. Reinstall Status**: After every change made to the codebase, always explicitly inform the user whether that specific change can be updated dynamically Over-the-Air (OTA) (e.g., by updating the `layout_config.json` via GitHub updates) or if it requires building and reinstalling the application (due to native Kotlin code, layout resource, manifest, or dependency modifications).

- **Architecting OTA-First Customizations**: When implementing or altering features (such as entities, controls, titles, statuses, colors, theme variables, or threshold limits), always avoid hardcoding them directly in Kotlin. Instead, configure and retrieve these properties dynamically from the live `layout_config.json` (accessed via `layoutConfig` state flow). This allows users to tweak, override, or extend these features on-the-fly dynamically OTA without needing a full application rebuild or reinstall.

- **How the app reaches the devices**: APK installs and updates come through Obtainium from the releases of `cstone1983/app-builder`, titled "hvac <version>". That repo checks out `main`, builds `:app:assembleRelease` unsigned, signs it with the shared release key and publishes a pre-release; promoting it to a full release deploys it. So "requires a reinstall" now means: push to `main`, run app-builder, promote the release. Do not sideload over the devices with adb; a `panel` or `debug` build is signed with a different key and will not install over an app-builder release.

- **Release build rules**: keep `versionName` plain dotted numbers (app-builder appends its run number, e.g. "82.0.57") and `versionCode` below 1000 (app-builder uses 1000 + run). Keep the `release` build type the same app as `panel`: not debuggable, R8 off, no build-type specific sources. app-builder has no `.env`, so a release has no Home Assistant token, no main Home Assistant address and no GitHub token built in; never make the app depend on a value from `.env`, and never commit one, because both this repo and the releases are public.

- **This repo publishes no APK**: `.github/workflows/android-release.yml` is a build check only (unit tests plus the unsigned release build). The in-app layout update reads `layout_config.json` from the branch and does not use GitHub releases.
