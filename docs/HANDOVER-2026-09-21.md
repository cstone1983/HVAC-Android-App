## Facts worth not rediscovering

**The heat pumps cannot go below 61 °F.** They work in 0.5 °C steps from a 16.0 °C floor. Home
Assistant advertises `min_temp: 60` because it rounds 60.8 down, but validates against the
unrounded value — so a write of 60 is rejected outright and the head silently keeps its previous
setpoint. Measured on the real heads: **60 rejected, 60.5 rejected, 61 accepted** (`set_tmp 160`).
Fujitsu's own app labels that same rung "60"; HA labels it "61". Same physical setpoint.

There is a matching floor on the cooling side at 64.5 °F (18 °C), which already existed.
`HEAT_FLOOR_F = 61.0` and `COOL_FLOOR_F = 64.5` now live in `HvacModels.kt`, and the same values
are duplicated in the n8n Controller and Watchdog. **If one changes, all three must.**

**The app had never once opened its WebSocket in production.** `getString("ha_token", "")` returns
`""` rather than null, so the `?:` fallback to BuildConfig was dead code and every
`if (token.isNotEmpty())` guard failed silently. REST covered for it, so nothing looked wrong. The
sting was that `awaitHeadState` falls back to a fixed 1.5 s sleep when the socket is down, which
quietly disabled the turn_on-before-mode ordering. Fixed via `resolveHaToken()`; all three devices
now authenticate.

**Both garage wired sensors report the opposite of the doors.** `binary_sensor.*_wired_sensor`
reads `on` while `cover.*_garage_door` reads `closed`. Use the cover entities.

**n8n `update_workflow` writes the draft only.** Always `publish_workflow` afterwards and confirm
`versionId == activeVersionId`. See `N8N-EDITING.md`.

**`ha_set_integration` is blocked** by the auto-mode classifier as "[Modify Shared Resources]",
the same class of block the n8n tools had before allow rules were added. It is per-tool, so the
n8n rules do not cover HA config tools.

## Operational notes

- Deploy targets are exactly three: **SM-X200** (Tab A8), **SM-X110** (Tab A9), **SM-F966U1**
  (Z Fold 7). A fourth device may appear over adb and must never receive the app.
- The Fold needs `adb shell screencap -p /sdcard/x.png` then `pull` — piping `exec-out screencap`
  gets corrupted by a multiple-display warning. Also set `MSYS_NO_PATHCONV=1` in Git Bash or
  `/sdcard/...` gets rewritten to a Windows path.
- A `while read` loop over `adb devices` only processes the first device: `adb shell` eats stdin.
  Use `for s in $SERIALS` with `</dev/null` on each adb call.
- The Fold's wireless debugging pairing does not survive reboots. Re-pair by reading the pairing
  port from `adb mdns services` (`_adb-tls-pairing._tcp`) and running `adb pair <ip>:<port> <code>`.
  The pairing port differs from the connect port, and both change.

**Never tap coordinates without taking a fresh screenshot first.** Doing so set the whole house
to HEAT mid-session: the idle timer had returned the panel to the Home tab, so a tap aimed at the
keypad landed on the house-mode row. Seven heads came on and all six zones latched into override.
That specific hole is now closed (the idle timer is suppressed while the keypad is up) but the
habit is the real fix.

## Alarm tab — current state

**Hidden.** `layout_config.json` → the `alarm` tab has `"hidden": true`. The code ships; only the
button is withheld. To reveal it, set that to `false`, push, and the panels pick it up on their
next update check — no rebuild, no reinstall.

Built and working:

- Status card reading a configurable panel entity, defaulting to `alarm_control_panel.alarmo`
- Sensor list handling three kinds, inferred from Home Assistant's `device_class`:
  contacts/covers → OPEN / CLOSED, motion and occupancy → DETECTED / CLEAR, each with its own icon
- Header swap: on this tab only, humidity/presence/room temps/weather are replaced by an
  armed-status card and an open-vs-clear count
- Keypad as a root-level dialog so it floats over any tab; masked entry, one-minute inactivity
  timeout, live countdown wired for the entry delay
- Opening the keypad switches to the alarm tab behind it, so closing it leaves you there; the
  normal idle timer then restarts

**Not tested against a real panel.** Alarmo was not installed when this was built. Everything
alarm-side degrades to `ALARM UNAVAILABLE` rather than rendering a plausible DISARMED. 16 unit
tests in `AlarmStateTest.kt` cover the logic that could not be exercised. The sensor list is live
and correct.

Handover points for whoever builds the HA side:

- If Alarmo's entity id is not `alarm_control_panel.alarmo`, change `alarm.entityId` in
  `layout_config.json`. One line, no rebuild.
- Arm buttons are derived from the panel's `supported_features`, so whichever modes are
  configured in Alarmo are the ones that appear. Nothing is hardcoded.
- The PIN is typed on the keypad and passed straight to the service call. It is never stored,
  cached or logged, and there is deliberately no config field for it. Keep it that way.

## Still open

**Deferred by choice:**

- **Run mutex (n8n).** All eight `Dispatch Zone - *` nodes use `waitForSubWorkflow: false`, so the
  mutex is released ~11 s before the writes it guards land. Fixing it means flipping that flag
  **and** raising the 150 s mutex TTL in the same change — a full sweep is ~350 s. Most
  behaviour-changing edit on the list.
- **OTA / CI signing.** There is no APK update path at all: the updater only ever pulls
  `layout_config.json`. CI runs `assembleDebug` with a fresh keystore each run, so its builds
  cannot install over anything, including each other. Needs a keystore in GitHub secrets plus a
  one-time uninstall/reinstall on all three panels.

**Known and unfixed (n8n):**

- **N6/N8** — the echo gate's read side still checks only `last_write_at`, so a fan/vane write's
  own echo is not suppressed, and a genuine vane change within 15 s of a mode change is dropped.
  Needs `Check Recent Self-Write` split by channel.
- **N7** — an unconfirmed write is reported to the Zone Runner as success, so the sequence
  continues into a head that may still be off.
- **Bot N11** — `Check Verify` excludes overridden/disabled zones from both numerator and
  denominator, so it can report "5 of 5 confirmed" while a held zone sits on the opposing family.

**Declined:** token rotation (HA long-lived token and GitHub PAT stay as they are).
