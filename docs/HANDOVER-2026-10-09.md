## What changed

**The alarm tab is wired to the real Alarmo panel.** Arm buttons derive from `supported_features`
(14 — away and night only). Sensor list mirrors Alarmo's six enabled sensors. Disarming routes to
the keypad, arming does not. Full detail in §4.5 and §6.10.

**The panels sound when the alarm triggers.** `AlarmSiren`, per device by model, max alarm volume
restored on stop, `USAGE_ALARM`, looped, triggered-only. Settings toggle to override.

**The screen wakes for an alarm**, so the keypad is visible on a dark panel.

**Two bugs found by Chris using it**, both mine:

- The keypad closed itself on a disarmed house. `phase == DISARMED && showing` fires on every
  state push, not on the transition. Looked like a crash.
- The siren would have fired on the Fold. I used Android's 600dp tablet threshold; the Fold is
  ~750dp unfolded. Caught before it shipped, but only just.

### Eight Sleep — blocked on Chris, half-finished

**State:** the broken fork (`grantnedwards/eight-sleep`) was removed and
`lukas-clarke/eight_sleep` v1.0.24 installed on 2 Oct. **It has never been activated.**

Still needed, in order:
1. Restart Home Assistant
2. Settings → Devices & Services → delete the old broken Eight Sleep config entry
3. Add Integration → Eight Sleep → OAuth2 flow (needs Chris's credentials; Claude cannot)

Removing the old config entry was **refused by the permission layer** when attempted — the
classifier judged it too destructive. Do not route around it; it is a UI click.

**Why it was replaced:** every control service on the old fork 500s —
`'EightUser' object has no attribute 'side_on'` / `'start_away_mode'`. The component and its
bundled `pyEight` were mismatched. It could read everything and control nothing.

**The automation Chris wants**, once the integration works: n8n turns on his side and/or Jessy's
at a set time, gated on whether that person is home, with the app's own presets left alone. He
will disable bedtime in the Eight Sleep app.

**What was learned before it broke** (all still true, all worth not rediscovering):

- One Pod 5, two physical sides. Chris has one permanently; the other is **shared** — Jessy or
  Ashley, whoever is staying. Neither lives there.
- **Only the profile currently assigned to a side exists in HA.** The other goes `unavailable`
  entirely — all its entities, simultaneously. Verified: Ashley's went unavailable at
  2026-10-01 05:20:52, Jessy's came alive 12 seconds earlier. So the automation cannot address
  "Ashley's side" while Jessy is assigned, and **HA has no service that reassigns a profile** —
  that swap happens in the Eight Sleep app.
- The bed **cools far more than it heats**. All three profiles have hit 55.4 °F. Treat it as a
  temperature target, not a heater.
- Chris's side runs a nightly session ~00:30→08:15 regardless of presence. Jessy's is ad hoc.
- The app's own three-phase profile is `smart:bedtime → smart:initial → smart:final → alarm`, and
  the levels **adapt night to night** (initial was +3 one night, −30 another). Driving fixed
  levels from n8n loses that; gating the session on presence keeps it.
- The recorder only holds ~11 days. **Long-term statistics go back five months** and were how
  Ashley's 23–27 Sep visit was found. Use `source="statistics"` for anything older than a week.

## Things that bit, and would again

**The permission layer silently refuses some HA writes.** `ha_set_integration` and the config
entry delete were both refused. Tell Chris rather than working around it.

**mDNS lists ports that are refused.** Wireless debugging rotates ports on restart. If every
target refuses, the setting needs re-enabling on the device.

**Source files are CRLF.** Python string replacement with `\n` silently matches nothing. Use the
Edit tool, or handle `\r\n`.

**Measure the right thing.** A day was spent reducing GC churn that turned out to be flat and
irrelevant — the pauses were sub-millisecond. The actual lag was a 400 ms UI stall from building
~9,000 `SimpleDateFormat`/`Calendar` objects on the UI thread. `dumpsys gfxinfo` percentiles under
interaction found it in minutes; allocation metrics never would have.
